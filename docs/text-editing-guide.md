# CRITIQUER 문구 수정 가이드

앱 문구는 대부분 코드 안의 문자열로 들어 있습니다. 문구만 바꾸고 싶다면 아래 파일을 먼저 보면 됩니다.

## 가장 자주 고치는 파일

- `lib/i18n.ts`: 첫 화면, 입력 폼, 로딩 화면, 결과 화면의 기본 문구
- `lib/mock-data.ts`: 크리틱 렌즈 카드, 선택 옵션, API 실패 시 보이는 샘플 결과
- `lib/ai/prompts/common-critique.ts`: AI가 공통으로 따라야 하는 크리틱 작성 규칙
- `lib/ai/prompts/critic-critique.ts`: 선택한 렌즈별로 AI에게 전달하는 크리틱 지시문
- `app/api/critique/route.ts`: API 키 오류, 입력 오류 같은 서버 오류 문구

## 직접 고칠 때 안전한 방법

1. 따옴표 안의 문장만 고칩니다.
2. `ko`는 한국어 문구, `en`은 영어 문구입니다.
3. `navAction`, `headline`, `description` 같은 왼쪽 이름은 코드가 찾는 이름이라 바꾸지 않습니다.
4. 저장하면 개발 서버가 켜져 있을 때 브라우저가 자동으로 새로고침됩니다.
5. 이상하면 터미널에서 `npm run typecheck`를 실행해 문법 오류를 확인합니다.

## 용어 기준

- `critique`는 한국어에서 `크리틱`으로 씁니다.
- `critic`은 화면에서는 보통 `크리틱 렌즈`라고 씁니다.
- 실제 인물을 흉내 내는 표현은 피하고, `관점`, `렌즈`, `판단 기준`처럼 설명합니다.

나중에 문구를 더 쉽게 고치고 싶다면, 코드 밖의 `content` 파일이나 간단한 관리자 화면으로 분리할 수 있습니다. 지금은 개발 속도를 위해 코드 안에 모아둔 상태입니다.
